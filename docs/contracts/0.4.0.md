## Who is calling (`contracts/auth-context.ts`)

`Context.auth.kind` is `cookie_session` (with `csrfVerified`), `agent_token`,
`oauth_access_token` or `api_key`, filled from the credential the transport verified. Access
levels map onto it positively:

- `human`, `human_admin`: `cookie_session && csrfVerified` (plus the admin role).
- `session`, `admin`: `cookie_session`. `/rpc` accepts no other credential, so a token can never
  reach these even if a route is added by mistake.
- `agent`: a cookie session (the web app) or an MCP token whose tool names the procedure. Agent-only
  refusals (Relay-only nodes, `restartRunning` skips, `profile_apply` refused whole) apply when
  `kind !== "cookie_session"`.
- `public`: `app.config`, `auth.verifyEmailTransport`.

The contract test calls the rule with a cookie without CSRF, a Full agent token, an OAuth token and
an API key for every human, session and admin procedure.

## Relay 3.0 semantics fixed here

- **Held definitions are versions.** A node holds every server-origin version it was sent and not
  told to drop (current, profile-pinned, running), keyed by `versionId`; several versions of one
  runtime are normal. `remove`, `keep` and define results name versions; the 128 cap counts
  versions; the frozen copy is the same set. A routine edit never removes the version a running
  instance launched from.
- **Chunked define.** A define operation is split by bytes (`CHUNK_BUDGET_BYTES`, 60 KiB, under the
  64 KiB control cap; one spec is at most 48 KiB so one envelope always fits). The node applies the
  operation after the `final` chunk and answers every chunk; only the final answer carries `held`,
  `heldMetricCommandsHash`, `heldPortRange` and `frozen`. `complete: true` means the operation
  carries the whole server-origin set: afterwards the node holds exactly `put` ∪ `keep` and drops
  every other server-origin version (`remove` is then not allowed).
- **Chunked inventory.** `runtime.inventory` chunks stop at `CHUNK_BUDGET_BYTES`; one always-on entry
  that would not fit is cut down (engine facts, then models) and marked `truncated`. `hello` no
  longer carries runtimes: `runtime.inventory` follows `hello.ok`.
- `hello.ok.definitionSync`: `expect` = a `runtime.define` operation follows before any job, so the
  node must not report missing definitions yet; `none` = the node is Relay only or nothing differs.
  The server never sends its view of trust; the node's value rules.
- **Hash safety.** `launchHash = sha256(canonicalJson(spec))` is the only definition identity a node
  sees. The node hashes `spec` exactly as received; the server hashes the parsed spec, so
  `runtimeSpecSchema` never transforms (no `.trim()`, `.default()`, coercion: padded text is refused)
  and every spec number is in the canonical range. `frames.test.ts` checks that parsing leaves every
  fixture canonically identical. `contentHash` is server-only.
- `runtime.job` carries no command text; the node renders from the held/frozen version with that
  `launchHash` after typing every placeholder. `runtime.job.result.detail` names the failed check
  (a path, never a value).
- Unit names are `wsmp-<handle>-r<rank>`; instance handles are `i-<id12>`, always-on handles the
  runtime slug (runtime slugs shaped `i-<id12>` are refused, by the server and by
  `wsmp runtime add`).
- Frozen peers are `{runtimeId, headAddr}` (no peer slugs: jobs carry only `head_addr`), reported in
  `trust.frozenPeers` and stored in `Node.frozenPeers`.
- Canonical JSON: keys by code point, no whitespace, `JSON.stringify` string escapes, integers
  within ±(2^53−1), other numbers 1e-6 ≤ |x| < 1e15 in shortest form without exponent.

## Decisions taken where the spec was open

1. **Frame module location.** The zod frames live with the server's relay code
   (`apps/server/src/relay/frames.ts`) rather than `packages/config/src/relay-3.0.ts` (§9.1):
   `packages/config` has no zod dependency and the runtime spec it embeds lives in `packages/api`.
   `protocol.ts` becomes the codec around it in S0b. The Rust mirror is a submodule of
   `protocol.rs`.
2. **Subprotocol** bumps to `ws-model-proxy.relay.v3` with the version.
3. **Kept frames, two renames:** `endpointSlug` → `handle` (`relay.request`, `stt.open`); `file.op`
   drops `mode`/`readGrant` and `file.rejected` reasons become `trust_relay`/`no_roots`.
   `relay.response.headers` accepts ordered pairs only; `relay.request` methods are GET/POST.
4. **`runtime.job`** sends a relative `timeoutMs` instead of an absolute deadline and adds `handle`;
   `rank`/`nnodes` stay job fields (the node checks `nnodes` against the held `groupSize`).
5. **Node part of the definition**: hello and the final define answer report
   `heldMetricCommandsHash` (matches the `Node` column) and `heldPortRange`.
6. **`runtime.inventory`**: instance records carry `launchVersionId` + `launchHash`; always-on entries
   carry `spec` only for node-origin runtimes; served-model capabilities on the wire are the
   `ModelCapability` list (0.3 capability profiles and `desiredCapabilities` are gone).
7. **Hello** keeps the terminal key agreement fields (`node.terminalPublicKey`,
   `node.terminalIdentity`).
8. **Engine facts**: source `custom` → `reader`, count context `adapter_count` → `reader_count`.
9. **Runtime spec**: kind = `launch` xor `address`; wire enums lower-case; resources add `none` and
   discrete `vendor`; fixed ports 1024–65535 (as the node requires); readiness timeout up to 1 h;
   reader interval 2–60 s; `divideBy` names another series; metric command format `lines` is
   `<metric> <value>` per line; `address.baseUrl` must be written in its normalized form with
   host `localhost` or an IP literal (the node decides which IPs via `runtimeHosts`).
10. **Enum casing**: every Prisma enum, in oRPC/MCP inputs and outputs, uses the upper-case Prisma
    values, including the registry's `engineLoadGate` (`AUTO`/`ENFORCE`/`OBSERVE`). Values that
    exist only inside JSON (`advanced`/`overrides` keys such as `countStrategy`,
    `protection.share`, `recommendedSurface`) and relay wire values are lower-case. No mapping
    layer is needed for any column.
11. **Kept routers**: `users` keeps `archive`/`unarchive` (the spec's ban/unban); `auth` is unchanged;
    root `appConfig`/`deploymentFlags`/`deploymentFeatures` become `app.config` / `app.flags` /
    `app.features`; settings split into per-user `settings` and `adminSettings`.
12. **Tools that wrap several procedures**: `pools_get` (`history: true` adds the history list),
    `runtimes_get` (`versions`, `versionId`), `providers_get` (accounts + models: two reads, no
    transaction needed), `runtime_update` (with `modelCapabilities`: the overrides and the new
    version commit in ONE transaction, or neither). `runtime_start` covers restarts
    (`instanceId`); there is no separate restart procedure. Deletes and command runs require
    `confirm` on MCP; the procedures take it optionally (the web confirms in a dialog).
13. **Previews** (`runtimes.start`, `profiles.apply`) return a `fingerprint`. People (cookie
    callers) must echo it: without one the call is refused `preview_required`, with a stale one
    `preview_stale`, so a person applies exactly the stop set they saw. Agents may omit it (they
    preempt without confirmation, owner decision).
14. **Spend caps**: `providers.spendCaps.*` sets provider-account caps; share caps are part of
    `access.shares.create/update`.
15. **Advanced registries** are plain data in `packages/config` with the 0.4-dev defaults and CHECK
    bounds; `overrides` groups `affinity` and `protection`.
16. **Metrics**: valid `groupBy` per scope and family is a table in `contracts/metrics.ts`; ranges
    are capped per family by what the tables keep (requests 30 days per minute, 13 months per
    hour; engine load 8 days; node gauges 7 days). `histogramVersion: "v1"` is
    `LATENCY_HISTOGRAM_BOUNDS_MS`. Load and node metrics carry no pool key, so a pool scope follows
    the pool's current members. `model_test` counts against the 2/min limit only with `bench`.
17. **Sitemap**: drafted in `docs/contracts/` and moved into `sitemap.md` by S0c.
18. **Interactive steps** (review #4/#5): people attach, reopen or cancel by step id
    (`runtimes.steps.*`, human, also on Relay-only nodes). Step views carry the command text
    (unrendered) and its author, plus `terminalOpen`; no view carries a terminal id.
19. **Lower dialog** (review #6): `nodes.lowerTrustPreview` lists, before the click, the
    definitions and metric commands that freeze (agent-written ones flagged), multi-node runtimes
    without a frozen peer set, and what stops working.
20. **Refusal reasons** are one enum (`contracts/refusals.ts`), continuing the 0.4-dev planner
    reasons with the 0.4.0 nouns.
21. **Test page on `/v1`** (`http.ts`): session cookie + same-origin `Origin` + `x-wsmp-test: 1`
    (`?test=1` for the realtime WebSocket); a direct served model is named
    `runtime:<runtimeId>:<upstreamModelId>`, refused with an API key.
22. **Custom node metrics**: up to 256 values per sample (16 commands × 16); label values are free
    text without control characters.

### Review cuts

Applied: `Node.definitionsFrozen` (frozen ⇔ trust RELAY), `runtimes.restart`, `hello.runtimes`,
`nodeTrustViewSchema.raiseCommand` (a web constant now), frozen-peer slugs. Changed instead of
cut: the redundant `ExecutionTarget` unique. Prisma requires `@@unique([providerModelId, userId])`
for the 1:1 relation through the owner-composite FK, so the single-column
`providerModelId @unique` went instead.

### Assigned to later chunks (non-blocking review items)

- C1–C3: the node also enforces the TS cross-field rules: Rust `validate()` already covers rank <
  nnodes, unit names, frozen ⇔ relay, envelope kind, define complete/keep/remove, and result
  final/held, against the shared `semantic-*` vectors. Hidden-character text rules get shared
  vectors in C2. `term.open` for a browser shell is refused at Relay only; operator terminals are
  recognized only by the `terminalId` of a received `runtime.job.operator`.
- S0b: remove the 2.4 supervised schemas from `file-protocol.ts`.
- B1/B2: share deletion also removes the grantee's `ApiKeyPool` rows and sidecar links to the pool
  (hardening `api_key_pool_access`); admission re-checks `canUse`.
