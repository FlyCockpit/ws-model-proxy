## Access levels (`contracts/procedure.ts`)

`public` (two kept plumbing queries), `session` (signed-in web app, never MCP), `agent`
(signed-in, also reachable through the MCP tools it names), `human` (positive check: cookie
session + CSRF/origin + no agent marker), `admin`, `human_admin`. The contract test enforces: every
`agent` procedure names its tools and each tool names it back; read tools call queries only;
every `session` procedure is on MCP or on the exclusion list with a reason; the API's enum values
equal the Prisma enums; tool names and descriptions avoid the §1.2 banned words; every tool
schema converts to JSON Schema.

## Relay 3.0 semantics fixed here (N9 and the S0b items)

- `hello.ok.definitionSync`: `expect` = a `runtime.define` diff follows before any job, so the
  node must not report missing definitions yet; `none` = the node is Relay only or nothing
  differs. The server never sends its view of trust; the node's value rules.
- `runtime.define.result.held` is the node's complete held set after applying the frame; the
  server replaces `Node.heldDefinitions` with it. `heldMetricCommandsHash` / `heldPortRange`
  describe the node part.
- `launchHash = sha256(canonicalJson(spec))` is the only definition identity a node sees
  (envelopes, held/frozen records, every `runtime.job`). The node hashes `spec` exactly as
  received. `contentHash` is server-only.
- `runtime.job` carries no command text: the node renders from the held/frozen definition with
  that `launchHash`, after typing every placeholder (decimals as canonical strings).
- Unit names are `wsmp-<handle>-r<rank>`; instance handles are `i-<id12>`, always-on handles the
  runtime slug (runtime slugs that look like `i-<id12>` are refused).
- Canonical JSON: keys by code point, no whitespace, `JSON.stringify` string escapes, integers
  within ±(2^53−1), other numbers 1e-6 ≤ |x| < 1e15 in shortest form without exponent.

## Decisions taken where the spec was open

1. **Frame module location.** The zod frames live with the server's relay code
   (`apps/server/src/relay/frames.ts`, as requested) rather than `packages/config/src/relay-3.0.ts`
   (§9.1): `packages/config` has no zod dependency and the runtime spec it embeds lives in
   `packages/api`. `protocol.ts` becomes the codec around it in S0b. The Rust mirror is a
   submodule of `protocol.rs` so the 2.4 code keeps compiling until S0b rewrites it.
2. **Subprotocol** bumps to `ws-model-proxy.relay.v3` with the version.
3. **Kept frames, two renames:** `endpointSlug` → `handle` (`relay.request`, `stt.open`;
   "endpoint" is a banned word and the node routes by handle); `file.op` drops `mode`/`readGrant`
   and `file.rejected` reasons `supervised_only`/`grant_disabled`/`feature_disabled` become
   `trust_relay`/`no_roots`. `relay.response.headers` accepts ordered pairs only; `relay.request`
   methods are GET/POST.
4. **`runtime.job`** sends a relative `timeoutMs` instead of an absolute `deadline` (no clock-skew
   dependency; the server keeps `InstanceStep.deadline`), adds `handle`, and keeps `rank`/`nnodes`
   as job fields (the node fills `{{node_rank}}`/`{{nnodes}}` from them after checking `nnodes`
   against the held `groupSize`).
5. **Node part of the definition**: hello and `runtime.define.result` report
   `heldMetricCommandsHash` (matches the `Node` column) and `heldPortRange` instead of one
   `heldNodeHash`.
6. **`runtime.inventory`**: instance records carry `launchVersionId` + `launchHash`; always-on
   entries carry `spec` only for node-origin runtimes; served-model capabilities on the wire are the
   `ModelCapability` list (the 0.3 capability profiles and `desiredCapabilities` are gone:
   overrides live on the server).
7. **Hello** keeps the terminal key agreement fields (`node.terminalPublicKey`,
   `node.terminalIdentity`) that 2.4 carried in `cli.capabilities`.
8. **Engine facts**: source `custom` → `reader`, count context `adapter_count` → `reader_count`.
9. **Runtime spec**: kind = `launch` xor `address`; wire enums lower-case (`llama_cpp`,
   `text_generation`); resources add `none` and discrete `vendor`; readiness timeout up to 1 h;
   reader interval 2–60 s; `divideBy` names another series; metric command format `lines` is
   `<metric> <value>` per line, and json/prometheus without `map` record one value under the
   command's name; the server already refuses hostnames in `address.baseUrl` (localhost or IP
   literal only; the node decides which IPs via `runtimeHosts`).
10. **API enum casing**: oRPC/MCP use the Prisma values (upper-case); relay and registry values
    are lower-case wire strings.
11. **Kept routers**: `users` keeps `archive`/`unarchive` (the spec's ban/unban); `auth` is
    unchanged; root `appConfig`/`deploymentFlags`/`deploymentFeatures` become `app.config` /
    `app.flags` / `app.features`; the 0.3 `settings` router splits into per-user `settings` and
    `adminSettings`.
12. **Tools**: `providers_get` wraps `providers.accounts.list` + `providers.models.list`;
    `runtimes_get` also takes `versionId` (one version's full definition); `runtime_update` also
    takes `modelCapabilities` (wraps `runtimes.models.setCapabilities`). Deletes and command runs
    require `confirm` on MCP; the procedures take it optionally (the web confirms in a dialog).
13. **Previews** (`runtimes.start/restart`, `profiles.apply`) return a `fingerprint`; people
    echo it to apply exactly what they saw; agents may omit it (no confirmation, owner decision).
14. **Spend caps**: `providers.spendCaps.*` sets provider-account caps; share caps are part of
    `access.shares.create/update`.
15. **Advanced registries** are plain data in `packages/config` (no zod there) with the 0.4-dev
    defaults and CHECK bounds; `overrides` groups `affinity` and `protection`;
    `recommendedSurface` values are lower-case.
16. **Metrics**: valid `groupBy` per scope and metric family is a table in `contracts/metrics.ts`;
    minute steps cover 30 days, history 13 months; `includeAgentTests` defaults to true for agents
    (the Overview excludes them).
17. **Sitemap**: drafted in `docs/contracts/` and moved into `sitemap.md` by S0c, because
    `sitemap.md` must describe the routes that exist.

## What builds today (end of the S0-0 step)

- `prisma validate` and `prisma format --check` pass on the new schema. `pnpm db:validate` as a
  whole fails at its last step: `verify-schema-hardening.mjs` still verifies the 0.3 hardening SQL
  against the 0.3 schema; S0a replaces both.
- The contract modules type-check in isolation (`frames.ts`, `runtime-spec.ts`,
  `canonical-json.ts`, `runtime-launch-hash.ts`, `contracts/*.ts`, the two registries).
- Tests: `apps/server/src/relay/frames.test.ts` (8) and `packages/api/src/contracts/contracts.test.ts`
  (11) pass; Rust `protocol::frames` and `protocol::canonical` tests pass, and `cargo clippy -D
  warnings` / `cargo fmt --check` are clean for the whole CLI crate.
- The rest of the repository still compiles only against the Prisma client generated from the
  0.3 schema; regenerating the client breaks every module that uses removed models. That is the
  expected state until the end of the S0 series (B4).
