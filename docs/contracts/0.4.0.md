## Who is calling (`contracts/auth-context.ts`)

`Context.auth.kind` is `cookie_session` (with `csrfVerified`), `agent_token`,
`oauth_access_token` or `api_key`, filled from the credential the transport verified.
`csrfVerified` is true only when the request carried an `x-csrf-token` header the server
validated against the session; CORS or Origin alone never sets it. The RPC layer requires that
header for every procedure in `CSRF_REQUIRED_PROCEDURES` (derived from the access tags: every
`human`/`human_admin` procedure, queries such as `nodes.lowerTrustPreview` included) on every
deployment shape, replacing the hand-kept list in `apps/server/src/csrf-policy.ts` (S0c). Access
levels map onto it positively:

- `human`, `human_admin`: `cookie_session && csrfVerified` (plus the admin role).
- `session`, `admin`: `cookie_session`. `/rpc` accepts no other credential, so a token can never
  reach these even if a route is added by mistake.
- `agent`: a cookie session (the web app) or an MCP token whose tool names the procedure. Agent-only
  refusals (Relay-only nodes, `restartRunning` skips, `profile_apply` refused whole) apply unless
  `isHumanCaller(auth)` (`agentRulesApply`): a cookie that failed the CSRF check is not a person.
  The D13 fingerprint is required exactly when `isHumanCaller(auth)`.
- `public`: `app.config`, `auth.verifyEmailTransport`.

The contract test calls the rule with a cookie without CSRF, a Full agent token, an OAuth token and
an API key for every human, session and admin procedure.

## Relay 3.0 semantics fixed here

- **Held definitions are versions.** A node holds every server-origin version it was sent and not
  told to drop (current, profile-pinned, running), keyed by `versionId`; several versions of one
  runtime are normal. `remove`, `keep` and define results name versions; the 128 cap counts
  versions; the frozen copy is the same set. A routine edit never removes the version a running
  instance launched from.
- **Chunked define.** A define operation is split by bytes (`CHUNK_BUDGET_BYTES`, 60 KiB, under the
  64 KiB control cap) and names at most 64 versions per chunk. Enforced caps (zod and Rust
  `validate()`): one spec ≤ 48 KiB canonical, so one envelope always fits; node metric commands
  ≤ 32 KiB together; a define answer and a `node.metrics` frame ≤ the chunk budget (the node
  drops custom values to fit); row ids ≤ 64 characters, which bounds the largest final answer
  (tested). The node applies the
  operation after the `final` chunk and answers every chunk; only the final answer carries `held`,
  `heldMetricCommandsHash`, `heldPortRange` and `frozen`. `complete: true` means the operation
  carries the whole server-origin set: afterwards the node holds exactly `put` ∪ `keep` and drops
  every other server-origin version (`remove` is then not allowed).
- **Chunked inventory.** `runtime.inventory` chunks stop at `CHUNK_BUDGET_BYTES`; one always-on entry
  that would not fit is cut down (engine facts, then models) and marked `truncated`. `hello` no
  longer carries runtimes: `runtime.inventory` follows `hello.ok`.
- `hello.ok.definitionSync`: `expect` = a `runtime.define` operation follows before any job, so the
  node must not report missing definitions yet; `none` = the node is Relay only or nothing differs.
  The server never sends its view of trust; the node's value rules.
- **Hash safety.** `launchHash = sha256(canonicalJson(spec))` is the only definition identity a node
  sees. The node hashes `spec` exactly as received; the server hashes the parsed spec, so
  `runtimeSpecSchema` never transforms (no `.trim()`, `.default()`, coercion: padded text is refused)
  and every spec number is in the canonical range. `frames.test.ts` checks that parsing leaves every
  fixture canonically identical. `contentHash` is server-only.
- `runtime.job` carries no command text; the node renders from the held/frozen version with that
  `launchHash` after typing every placeholder. `runtime.job.result.detail` names the failed check
  (a path, never a value).
- Unit names are `wsmp-<handle>-r<rank>`; instance handles are `i-<id12>`, always-on handles the
  runtime slug (runtime slugs shaped `i-<id12>` are refused by the server; a node-side
  runtime add command does not exist yet).
- Fabrics replace frozen peers (owner decisions round 3, below): the node part of
  `runtime.define` carries the node's fabric sets with their hash; at Relay only the node checks
  a multi-node job's `head_addr` against its frozen copy of the job's fabric.
- Canonical JSON: keys by code point, no whitespace, `JSON.stringify` string escapes, integers
  within ±(2^53−1), other numbers 1e-6 ≤ |x| < 1e15 in shortest form without exponent.

## Decisions taken where the spec was open

1. **Frame module location.** The zod frames live with the server's relay code
   (`apps/server/src/relay/frames.ts`) rather than `packages/config/src/relay-3.0.ts` (§9.1):
   `packages/config` has no zod dependency and the runtime spec it embeds lives in `packages/api`.
   `protocol.ts` becomes the codec around it in S0b. The Rust mirror is a submodule of
   `protocol.rs`.
2. **Subprotocol** bumps to `ws-model-proxy.relay.v3` with the version.
3. **Kept frames, two renames:** `endpointSlug` → `handle` (`relay.request`, `stt.open`); `file.op`
   drops `mode`/`readGrant` and `file.rejected` reasons become `trust_relay`/`no_roots`.
   `relay.response.headers` accepts ordered pairs only; `relay.request` methods are GET/POST.
4. **`runtime.job`** sends a relative `timeoutMs` instead of an absolute deadline and adds `handle`;
   `rank`/`nnodes` stay job fields (the node checks `nnodes` against the held `groupSize`).
5. **Node part of the definition**: hello and the final define answer report
   `heldMetricCommandsHash` (matches the `Node` column) and `heldPortRange`.
6. **`runtime.inventory`**: instance records carry `launchVersionId` + `launchHash`; always-on entries
   carry `spec` only for node-origin runtimes; served-model capabilities on the wire are the
   `ModelCapability` list (0.3 capability profiles and `desiredCapabilities` are gone).
7. **Hello** keeps the terminal key agreement fields (`node.terminalPublicKey`,
   `node.terminalIdentity`).
8. **Engine facts**: source `custom` → `reader`, count context `adapter_count` → `reader_count`.
9. **Runtime spec**: kind = `launch` xor `address`; wire enums lower-case; resources add `none` and
   discrete `vendor`; fixed ports 1024–65535 (as the node requires); readiness timeout up to 1 h;
   reader interval 2–60 s; `divideBy` names another series; metric command format `lines` is
   `<metric> <value>` per line; `address.baseUrl` must be written in its normalized form with
   host `localhost` or an IP literal (the node decides which IPs via `runtimeHosts`).
10. **Enum casing**: every Prisma enum, in oRPC/MCP inputs and outputs, uses the upper-case Prisma
    values, including the registry's `engineLoadGate` (`AUTO`/`ENFORCE`/`OBSERVE`). Values that
    exist only inside JSON (`advanced`/`overrides` keys such as `countStrategy`,
    `protection.share`, `recommendedSurface`) and relay wire values are lower-case. No mapping
    layer is needed for any column.
11. **Kept routers**: `users` keeps `archive`/`unarchive` (the spec's ban/unban); `auth` is unchanged;
    root `appConfig`/`deploymentFlags`/`deploymentFeatures` become `app.config` / `app.flags` /
    `app.features`; settings split into per-user `settings` and `adminSettings`.
12. **Tools that wrap several procedures**: `pools_get` (`history: true` adds the history list),
    `runtimes_get` (`versions`, `versionId`), `providers_get` (accounts + models: two reads, no
    transaction needed), `runtime_update` (with `modelCapabilities`: the overrides and the new
    version commit in ONE transaction, or neither). `runtime_start` covers restarts
    (`instanceId`); there is no separate restart procedure. Deletes and command runs require
    `confirm` on MCP; the procedures take it optionally (the web confirms in a dialog).
13. **Previews** (`runtimes.start`, `profiles.apply`) return a `fingerprint`. People (cookie
    callers) must echo it: without one the call is refused `preview_required`, with a stale one
    `preview_stale`, so a person applies exactly the stop set they saw. Agents may omit it (they
    preempt without confirmation, owner decision).
14. **Spend caps**: `providers.spendCaps.*` sets provider-account caps; share caps are part of
    `access.shares.create/update`.
15. **Advanced registries** are plain data in `packages/config` with the 0.4-dev defaults and CHECK
    bounds; `overrides` groups `affinity` and `protection`.
16. **Metrics**: valid `groupBy` per scope and family is a table in `contracts/metrics.ts`; ranges
    are capped per family by what the tables keep (requests 30 days per minute, 13 months per
    hour; engine load 8 days; node gauges 7 days). `histogramVersion: "v1"` is
    `LATENCY_HISTOGRAM_BOUNDS_MS`. Load and node metrics carry no pool key, so a pool scope follows
    the pool's current members. `model_test` counts against the 2/min limit only with `bench`.
17. **Sitemap**: drafted in `docs/contracts/` and moved into `sitemap.md` by S0c.
18. **Interactive steps** (review #4/#5): people attach, reopen or cancel by step id
    (`runtimes.steps.*`, human, also on Relay-only nodes). Step views carry the command text
    (unrendered) and its author, plus `terminalOpen`; no view carries a terminal id.
19. **Lower dialog** (review #6): `nodes.lowerTrustPreview` lists, before the click, the
    definitions and metric commands that freeze (agent-written ones flagged), the fabric
    memberships and secret names that freeze with the node, and what stops working.
20. **Refusal reasons** are one enum (`contracts/refusals.ts`), continuing the 0.4-dev planner
    reasons with the 0.4.0 nouns.
21. **Test page on `/v1`** (`http.ts`): session cookie + same-origin `Origin` + `x-wsmp-test: 1`
    (`?test=1` for the realtime WebSocket); a direct served model is named
    `runtime:<runtimeId>:<upstreamModelId>`, refused with an API key.
22. **Custom node metrics**: up to 256 values per sample (16 commands × 16); label values are free
    text without control characters.

## Owner decisions round 3 (2026-10-06, `claude-concept-audit.md` §10)

All in one contract commit, before the S0 wiring depends on them.

1. **Multi-use enrollment codes.** `NodeEnrollmentCode.maxUses` (1–50, default 1),
   `usedCount`, `lastUsedAt`, `labels` (added to every node enrolled with it),
   `removeAfterOfflineMs` (temporary nodes), revocable; one `NodeEnrollmentUse` row per exchange
   (which node, when). Still 130-bit codes, ≤ 7 days (default 1 h), rate-limited. A multi-use code
   takes no suggested slug; a Replace code is single-use and carries no labels or policy.
   Hardening: `node_enrollment_code_shape` (bounds), `node_enrollment_code_use` (created unused,
   +1 per exchange, never while revoked or expired, identity immutable),
   `node_enrollment_use_shape` (same owner, append-only).
2. **Contributor agents.** `pools.members.addContributed` / `removeContributed` and
   `runtimes.fork` are agent procedures. Through MCP: `pool_update.contribute.{add,withdraw}`
   (no new tool) and `runtime_create.forkFrom`; `runtimes_get shared` lists definitions shared with
   you. An agent may add only the caller's OWN served models (`not_your_runtime`) to a pool shared
   with the caller with can contribute, and withdraw only its own; the pool owner (person or
   owner agent) removes any contributed member.
3. **Share invites.** `ShareInvite` (pool, owner, lower-cased e-mail, token digest of
   `wsmp_inv_` + 26 base32, the share's settings, expiry ≤ 30 days, e-mail sent, accepted with the
   share it created, revoked). `access.shares.create` answers `share` or `invite` (a link is
   returned only when no e-mail could be sent); `access.invites.resend/revoke`; public
   `auth.inviteInfo` for the invite sign-up page (fails closed without its per-address limiter).
   Acceptance: a sign-up through the link (token in `x-wsmp-invite`, any e-mail, even with open
   sign-up off; the create hook claims the invite for the sign-up's e-mail in
   `signupClaimedAt`/`signupClaimedEmail`, outside the sign-up transaction, so one token makes one
   account: the same e-mail may take the claim over, another e-mail gets `INVITE_IN_USE` for 10
   minutes, and after that only if no account has the claimant e-mail; resend clears the claim),
   a signed-in person through `auth.acceptInvite` (human, per-user limit; the claimant account
   recovers an invite its sign-up failed to accept), or a proven e-mail match. Hardening: `share_invite_shape`,
   `share_invite_transition` (identity immutable, final once accepted or revoked, the accepted
   share is a share of this pool, whatever the grantee's e-mail: the link is the proof).
4. **Fabrics.** `Fabric {owner, name}` + `FabricMember {fabric, node, ip}` (an IP literal, not the
   unspecified address; one membership per node and fabric). Part of the node definition: edited
   by people and Full agents via `nodes.update.fabrics` (`node_update`), pushed as
   `runtime.define.node.fabrics {hash, sets[{fabricId, name, selfIp, memberIps}]}` and frozen at
   Relay only (`Node.fabricsHash` / `heldFabricsHash`, `frozenFabrics`). `launch.fabric` (name,
   multi-node only) pins one; otherwise placement picks any fabric with enough free members and
   never splits an instance (`no_shared_fabric`). Jobs carry `fabricId` and `head_addr` (the
   head's IP on it) exactly when `nnodes > 1`; the node derives `{{fabric_ip}}`,
   `{{fabric_iface}}`, `{{fabric_rdma_device}}` from its own IP (`/sys/class/net`, the RDMA device
   map); the server never sends interface names (`iface` is gone from specs and jobs). At Relay
   only the head must be in the node's frozen membership (`head_not_in_frozen_fabric`).
   `node.info.interfaces[].rdma` feeds suggestions only. `Node.frozenPeers` and
   `trust.frozenPeers` are removed; `no_frozen_peer_set` is retired (kept in the enum, never
   reused).
5. **Temporary nodes.** `removeAfterOfflineMs` on the code (applied to each node it enrolls) and on
   the node (`nodes.setTemporary`, human only: a deletion policy, never via `node_update`).
   Sweeper (A1, in `relay-maintenance.ts`): deletes such a node once offline that long, through
   the same delete path as a person's (claims released by `node_delete_release`, nothing stuck);
   index `(removeAfterOfflineMs, connection, lastDisconnectedAt)`.
6. **Bind address.** Single-node presets bind `127.0.0.1`; `runtimeSpecWarnings` flags 0.0.0.0/::
   (`binds_all_interfaces`, in create/update results and preview warnings), never refuses.
   Multi-node presets bind `{{fabric_ip}}`.
7. **Several runtimes per node** (checked, no change needed): instances on one node take distinct
   ports from the node range, the planner sums declared resources against the node's usable
   (unified) memory across every held claim, and a profile pins any number of items on one node.
8. **Services (no proxying).** A STARTABLE spec without `models` has no `api`/`engine`/`modelType`
   (`RuntimeVersion` columns nullable, `runtime_version_derived_columns` enforces both shapes),
   readiness by HTTP or a `status`/`health` command per rank, no metrics reader. It claims its
   declared resources (it may claim a whole node), has no served models, so it is never a pool
   member and never on the Models page. Nothing in the schema assumes an instance has served
   models or a pool.
9. **Node secrets.** One namespace `WSMP_SECRET_*` (replaces `WSMP_ENDPOINT_*`), referenced by
   name from address auth/headers and `launch.secrets` (exported to the commands). Write-only: at
   Full control people and Full agents set or delete them (`nodes.secrets.set` / `.delete`, see review fix 10; value in the
   `secret.set` frame only, never stored, logged or audited: `redactFrameForLog`, Rust `Debug`
   redaction); the node stores them 0600 and answers `secret.result` with the name only. At Relay
   only remote writes are refused (`secret_needs_node`); `wsmp secret set NAME` on a TTY. The
   node reports names and `updatedAt` in `features.secrets`.
10. **Node hold.** `Node.holdAt/holdNote/holdProfileId`; `nodes.setHold` (human); profile "hold
    node" lines (`ProfileNode.hold/holdNote`, people only; an agent's `profile_save` keeps them).
    While held the planner places nothing there for anyone (`node_held`). Applying a profile with
    a hold line stops wsmp runtimes on that node and holds it; applying one that owns the node
    without a hold line releases it.
11. **Node commands.** `node_command_run` answers within ~15 s (`state: running` and the output
    so far if still going); new tool `node_command_get {commandId, waitMs ≤ 30 s, cancel}`
    (26 tools); it also takes a `node_command_queue_for_user` id and answers that queued
    command's state (`queuedForUser: true`, no output; every id input accepts every minted id
    format, `contracts.test.ts` "id formats"). Lifetime: `timeoutMs` per call (default 1 h) capped by `Node.commandMaxMs` (node
    definition, 1 min–24 h, default 24 h; people or Full agents). The node kills the whole process
    tree at the end, on cancel and at the limit, keeps a bounded output ring buffer per command
    and a bounded table of recent commands, and reports commands a daemon restart interrupted.
    Frames: `exec.start{timeoutMs}`, `exec.poll{tailBytes ≤ 64 KiB}`, `exec.cancel`;
    `exec.started{startedAt, endsBy}`, `exec.status` (state, exit code, tail, truncated);
    `exec.done` and the binary `exec.stdout/stderr` are removed. The server stores state and
    timing in `NodeCommand` (no output; 30-day retention) and the outcome in the append-only
    `NodeAuditEvent`; output comes live from the node (null while it is offline).
12. **Token-efficient MCP.** Descriptions of 1–3 short sentences; large nested inputs
    (definitions, advanced settings, hardware, metric commands) are advertised as plain objects
    (`compactFields`, validated in full by the procedure). `tools/list` measured 13,223 tokens
    (chars/4, 25 tools) before and 5,506 after (26 tools); `contracts.test.ts` fails above 6,500.
    Long guidance (commands vs runtimes, prepare steps, definition shapes) goes to `docs/mcp.md`
    (E2) and to refusal messages.
13. **Node file tools** (`nodes.files.read/write/edit`, `src/nodes/files.ts` → server
    `relay/node-file-ops.ts`). Agents only (FULL agent token or OAuth grant; people use a
    browser terminal), on their own node at Full control (stored, live, no pending lowering) with
    `files.roots`. Each tool call is one relay op: `read` maps `offset/limit/ifNoneMatch` to
    `startLine/maxLines`, `stat` hashes (so it returns an etag), `list` takes `offset` as depth
    (1–4) and `pattern` as glob, `search` caps `limit` at 500 matches; `write` without `ifMatch`
    only creates (`ifExists: fail`), with it replaces exactly that etag; `mkdir` makes parents;
    `rename`/`delete` pass `ifMatch` as the expected etag; `edit` maps `{old, new, count}` to
    exact-text edits under `ifMatch`. A field that does not apply to the op is `invalid_input`.
    Content: at most 1 MiB decoded (strict base64 or well-formed UTF-8), in one `file.body`.
    The server refuses any path that is not absolute, has a `.`/`..` component or is not under
    a live root (`path_denied`, the message lists the roots) before sending; the node checks its
    roots again, symlink-safe, and its deny list (state dir, `service.env`, `config.json` read
    only). Errors keep the file code as `data.reason` (`conflict`, `exists`, `no_match`, …,
    `data.outcome: "unknown"` for a mutation the server cannot settle). One `NodeAuditEvent`
    per op (path, etags, bytes, outcome, credential; never content). A revoked credential or a
    ban ends its in-flight ops at once.
14. **OAuth grant level** (owner decision: agent access is Read-only or Full). The consent page
    offers Read-only (default, as in the agent token dialog) or Full when the client asked for
    `mcp:write`; the person's choice is the `level` field of the `/oauth2/consent` body only
    (`packages/auth/src/mcp-consent-level.ts`), recorded on the exact grant generation before
    the code reaches the browser; Full without `mcp:write` approved is refused. Remembered
    consent keeps the level; a step-up or `prompt=consent` re-prompt replaces it.
    `access.oauthGrants.setLevel {grantId, level} → {level}` (human) changes it in Access →
    Agents; Full only when the generation's remembered consent includes `mcp:write`
    (`oauthConnectionViewSchema.fullAvailable`). Lowering is read at the next lookup and ends the grant's Full work through
    `Context.services.onAccessLevelLowered` (in-flight write tool calls, node commands and file
    ops; queued commands expire `credential_lowered`); raising applies from the next call. Both
    writes are audited (`AuditEvent`, actor USER, resource `mcp_grant`, actions
    `mcp_grant.consent` / `mcp_grant.level`, `before`/`after` `{level}`).

### Contract review fixes (after `0e45154d`)

1. **Holds** (`lib/profile-holds.ts` `planProfileHolds`, tested): applying a profile holds the
   nodes with its hold lines (`holdProfileId` = the profile) unless someone else already holds
   them, and releases only holds it set itself. A person's or another profile's hold on an owned
   node without a hold line refuses an agent's apply whole (`node_held`); a person's apply,
   confirmed through the preview, releases it. `holdProfileId` is a foreign key (SET NULL: a
   deleted profile's holds become plain holds).
2. **Fabric IPs** (`lib/ip-literal.ts` `isFabricIp`, Rust `is_fabric_ip`, SQL
   `wsmp_is_fabric_ip`): exactly the canonical text of one address (dotted quad without
   leading zeros, RFC 5952 IPv6 without an embedded IPv4 part); never 0.0.0.0/8, loopback,
   `::/96` or IPv4-mapped. Brackets, zones, prefixes and anything else are refused. The three
   implementations run the same vectors (`relay-3.0/rules/fabric-ip.json`). `head_addr` uses
   the same rule in TS and in Rust `RuntimeJob::validate`.
3. **`removeAfterOfflineMs`** is `BigInt` in the database (up to 30 days); the contract keeps
   a JSON number.
4. **MCP budget**: the contract budget test measures the advertised list; the server's own
   test measures its real `tools/list` (titles, annotations, output schemas) — `apps/server/src/mcp`.
5. **Secret names in outputs** are never redacted (redaction is by value and by the sensitive
   procedures, not by key names containing "secret") — server MCP work.
6. **Invites**: resend rotates `tokenDigest` and `expiresAt` while pending; one pending invite
   per pool and e-mail (partial unique index), so a revoked or accepted e-mail can be invited
   again. `ShareInvite.shareId` is a foreign key (SET NULL).
7. **Invite acceptance** (`lib/invite-acceptance.ts`, tested): by the link's token always; by
   e-mail match only for a verified address. With verification off (no SMTP) only the link
   works (`invite_needs_link`).
8. **`RuntimeInstance.fabricId`** (composite FK to `Fabric`, RESTRICT): set for multi-node
   instances, cleared at STOPPED/FAILED. While set the fabric cannot be deleted and the members
   its ranks use keep their IPs (`fabric_member_in_use` trigger; refusal `fabric_in_use`).
9. **Lowering trust** kills running node commands with their process trees; the node reports
   them INTERRUPTED (`lowerTrustPreview.runningCommands` counts them). At Relay only `exec.poll`
   and `exec.cancel` are still answered (read and stop); `exec.start` is refused.
10. **Secrets** left `nodes.update`: `nodes.secrets.set` / `nodes.secrets.delete` (agent level,
    Full control), MCP tool `node_secret_set` (value null deletes; 27 tools). Both are listed in
    `SENSITIVE_INPUT_PROCEDURES` / `sensitiveInput`: never logged, audited (name only) or echoed.
11. **Temporary-node sweeper vs `pinned_by_profile`**: the sweeper removes the profile items
    that pin the node's always-on runtimes (recorded in the node activity), then deletes the
    node like a person's delete. A temporary node never gets stuck.
12. **`runtimes.fork`** returns `runtimeCreateOutputSchema` (`{runtime, version, define,
    warnings}`) and takes `limits`, `advanced` and `note` like create.
13. Nits: `binds_all_interfaces` also catches `http://0.0.0.0:…` and `vllm serve` without
    `--host`; node-derived `{{fabric_iface}}` / `{{fabric_rdma_device}}` values must pass
    `is_fabric_device_name` (letters, digits, `_ . : -`, not starting with `-`, ≤ 64) before
    substitution; Rust enforces the served/service spec shape (`RuntimeSpec::validate_shape`);
    `enrollmentCodes.create` takes `temporary: true` (1 h unless `removeAfterOfflineMs`).

      `models` of an always-on runtime whose spec lists none) is for always-on runtimes only.
