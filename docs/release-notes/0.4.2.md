# WS Model Proxy 0.4.2: upgrade notes

0.4.2 is a security and reliability release for the `wsmp` CLI. It removes
trust in a compromised certificate authority and fixes daemon installation
on macOS and Linux.

## Compromised eMudhra/emSign CA

In October 2026, eight eMudhra/emSign intermediate CA private keys were found to
be recoverable from their public certificates. Anyone holding those keys can
issue certificates for any domain, which could let an attacker intercept TLS
connections from clients that still trust the emSign root.

The CLI's bundled root store (used for HTTPS calls such as login, model probes,
and context counting) is updated to `webpki-roots` 1.0.10, which removes the
emSign ECC Root CA - G3. `rustls-webpki` is updated to 0.103.16. The relay
websocket uses the operating system's certificate store, so also keep each
node's OS certificates up to date.

The server container uses Node.js's bundled root store. Rebuild or pull a
newer image once a Node.js release blocking the compromised keys is available.
If your own deployment's TLS certificate was issued by eMudhra/emSign, replace
it with one from another certificate authority.

## Daemon installation

- macOS: `wsmp service install` and `wsmp service uninstall` no longer print
  `launchctl` errors such as `Boot-out failed: 5` when the agent is not loaded,
  which happened on every first install.
- Linux: `wsmp service install` checks whether systemd lingering is enabled. When
  it is off, the CLI warns that the node cannot start runtimes and the service
  stops at logout, and shows the `loginctl enable-linger` command to fix it.

## Upgrading from 0.4.1

Upgrade every node's `wsmp` CLI to 0.4.2. Reinstall it through your server's
`/install.sh` or your usual release installer, then restart its daemon.

Relay protocol remains **3.0**. 0.4.0 and 0.4.1 CLIs and servers remain
compatible with 0.4.2. There are no database schema changes and no new
configuration requirements.

The server's CLI installer targets the matching 0.4.2 release binaries. Publish
`v0.4.2` through the Release workflow from `master` before deploying this version,
or deploy its published container image so the installer assets are available.
