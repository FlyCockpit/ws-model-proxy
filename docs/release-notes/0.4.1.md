# WS Model Proxy 0.4.1: upgrade notes

0.4.1 adds image paste and drag-and-drop to browser terminals and fixes local
chat routing for models whose tool support is unknown.

## Images in browser terminals

On macOS and Linux nodes, paste or drop a PNG, JPEG, or WebP image into a
human browser terminal. The browser uploads it through the existing encrypted
terminal connection, then pastes the temporary file's absolute path without
sending Enter. The terminal application must support reading images from paths.

Images are limited to 8 MiB each. Completed files stay available until the
terminal session ends, including across browser detach and reattach. Operator
terminals do not accept image uploads. See
[Images in browser terminals](../../apps/cli/docs/terminal-images.md) for limits,
cleanup behavior, and clipboard text fallback.

## Local chat routing

Native requests can now reach the upstream when tool, parallel-tool,
structured-output, or reasoning support is unknown. This fixes local chat
requests with function tools being rejected before reaching models that
support them. Explicitly unsupported capabilities still reject requests, and
protocol adaptation keeps its existing feature limits.

## Upgrading from 0.4.0

Upgrade the server/web app and the node's `wsmp` CLI to 0.4.1 to use image paste.
Reinstall the CLI through your server's `/install.sh` or your usual release
installer, then restart its daemon and open a new terminal session.

Relay protocol remains **3.0**. Image upload is an optional encrypted extension
enabled only when the CLI advertises support. Existing 0.4.0 CLIs can continue
connecting to the upgraded server, and 0.4.1 CLIs can connect to a 0.4.0 server.
With an older CLI, the new browser falls back to clipboard text when available
or asks for a CLI update for an image-only paste.

There are no database schema changes from 0.4.0 and no new configuration
requirements. Upgrades from 0.3 still require the fresh installation described
in the [0.4.0 upgrade notes](0.4.0.md).

The server's CLI installer targets the matching 0.4.1 release binaries. Publish
`v0.4.1` through the Release workflow from `master` before deploying this version,
or deploy its published container image so the installer assets are available.
